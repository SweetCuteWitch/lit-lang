# Повторение без генерации: возврат заданий и рецепты упражнений

Дата: 2026-11-19 · Статус: черновик, ждёт утверждения пользователя

## Зачем
Сейчас каждое задание показывается один раз и уходит из банка (`status = served`), поэтому банк
закрепления тает и пользователю приходится звать Claude за новыми заданиями. При этом на слабые темы
в занятии приходится максимум 3 задания, а ошибочное задание больше не возвращается.

Пользователь хочет:
- больше закрепления и повторения, и чтобы для этого **не нужно было обращаться к Claude**;
- чтобы бот сам видел, где пользователь проседает, и давал по этим темам **больше 5 заданий**;
- чтобы **хорошо понятая тема не попадалась снова и снова**;
- разнообразия, а не только карточек «Помнишь перевод?».

Главное правило проекта остаётся: пользователь не может сам заметить ошибку в литовском, поэтому
корректность важнее разнообразия. Литовские формы бот не придумывает, а берёт из лексикона.

## Цели
1. **Возврат заданий.** Задания не расходуются: у каждого есть счётчик освоения 0–5 и дата следующего
   показа. Чем лучше задание сделано, тем реже оно возвращается.
2. **Учёт темы.** Шанс выдачи задания зависит и от успехов по его тегам: проседающие темы идут чаще и
   больше, освоенные (>90% верных) — реже.
3. **Рецепты упражнений.** Claude один раз описывает рецепт (рамки-предложения + список слов + нужная
   форма), CLI разворачивает его по лексикону в набор вариантов, бот сам делает из вариантов задания
   разных видов (вписать форму, выбрать кнопку, собрать фразу), когда своих заданий не хватает.
4. **Больше работы над ошибками в занятии закрепления:** ≥ 60% заданий — по слабым темам.

## Не-цели
- Бот не вызывает языковую модель и не генерирует литовский текст сам (вариант «В» отклонён).
- Перевод RU→LT и LT→RU из рецептов не делается: бот не склоняет русские слова. Перевод остаётся
  в заданиях, которые пишет Claude.
- Лексикон не загружается в бота (Vercel): всё, что нужно из лексикона, CLI сохраняет в рецепт заранее.
- Кнопки «Словарь» и «Уроки» — отдельная следующая задача, не здесь.

## Анти-цели (провал, даже если «работает»)
- Бот показывает неверную литовскую форму как правильную.
- Освоенная тема продолжает занимать заметную долю каждого занятия.
- Одно и то же задание приходит два дня подряд, хотя на него ответили верно.

## Подходы
- **А. Упражнения в коде** — отдельная функция на каждую тему (*būti*, *koks/kokia*, *iš* + род.).
  Надёжно, но каждая новая тема требует правки кода. Отклонён: не снимает зависимость от Claude.
- **Б. Рецепты как данные (выбран).** В коде — несколько универсальных видов рецептов, конкретные рецепты
  Claude добавляет через `bank add` вместе с уроками. Новая тема = новая запись, без кода.
- **В. Бот зовёт ИИ на лету.** Разнообразно, но непроверенные формы доходят до пользователя, нужен
  платный ключ. Отклонён: против главного правила корректности.

Возврат заданий со счётчиком пользователь одобрил отдельно; рецепты дополняют его, когда задания
по теме кончились или до их срока далеко.

## Часть 1. Возврат заданий

### Счётчик освоения
У задания поля `score` (0–5, по умолчанию 0) и `dueAt` (по умолчанию — сразу, т. е. `createdAt`).

После ответа на задание (в любом занятии, `new` или `review`):
| ответ | новый score |
|---|---|
| верно и точно (`exact`) | `min(score + 1, 5)` |
| верно без диакритики | без изменений |
| неверно / «Не знаю» | `0` |

Чтение (`reading`) с несколькими вопросами: задание верно, если все вопросы верны; неверно, если хоть
один неверен. Score обновляется один раз, после последнего вопроса.

Следующий показ — по **новому** score, в днях пользователя (Вильнюс):
`dueAt = dayStart(now) + INTERVAL[score] дней`, где `INTERVAL = [1, 3, 7, 14, 30, 60]`.
Значит: ошибка → завтра; первый верный ответ (0 → 1) → через 3 дня; score 5 → раз в 2 месяца.
Верный ответ никогда не возвращает задание на следующий день.

**Спор («Я ответил правильно»).** Нажатие кнопки ставит `score = 2`, `dueAt` по `INTERVAL[2]`
(прежний score не хранится — это дешёвое приближение). Если затем Claude в `disputes resolve`
выносит `verdict: "wrong"`, задание получает `score = 0`, `dueAt` = завтра. Вердикт `correct`
счётчик больше не меняет.

### Какие задания вращаются
- Все мгновенные задания (`choice`, `input`, `translate`, `order`, `reading`) обоих слотов. Задание
  порции (`slot = new`) после своего занятия тоже уходит в повторение — так пул сразу больше.
- `writing` не вращается: письмо выдаётся один раз, как сейчас.
- Задание участвует в повторении, только если `lessonNo ≤ текущий урок`, а для `slot = new` — только
  если его порция уже выдана.
- Статус `served` теперь значит «уже показывалось» (для отчётов и запаса), а не «израсходовано».
  `retired` — задание выведено из оборота (на будущее; сейчас никто не ставит).

### Учёт темы
Точность тега за 14 дней: доля верных ответов среди ответов на задания с этим тегом.
- **слабый тег**: ≥ 3 ошибок за 14 дней **или** точность < 70% (при ≥ 3 ответах);
- **освоенный тег**: точность ≥ 90% при ≥ 5 ответах и 0 ошибок за последние 7 дней;
- остальные — обычные.

Вес задания при выборе:
`вес = (6 − score) × множитель`, где множитель = 3, если у задания есть слабый тег; 0.3, если все его
теги освоенные; иначе 1. Слабый тег важнее освоенного (задание с обоими — ×3).

### Сборка занятия закрепления
Было: до 5 карточек слов + до 8 заданий (из них максимум 3 по слабым темам).
Станет (значения — решение Claude, легко поменять константами):
- до **3** карточек слов (`WORDS_PER_SESSION` 5 → 3) — меньше «Помнишь перевод?»;
- **10** заданий (`REVIEW_TASKS_PER_SESSION` 8 → 10);
- из них **≥ 6 по слабым темам**, если такие задания есть (своих или из рецептов); остальные — по весу.

Алгоритм:
1. Кандидаты — вращающиеся задания с `dueAt ≤ now`.
2. Слабая часть: кандидаты со слабыми тегами, взвешенный случайный выбор без повторов, до 6.
   Если их меньше 6 — добираются вариантами рецептов по слабым тегам (часть 2).
3. Остальное — взвешенный случайный выбор из всех оставшихся кандидатов; если их не хватает —
   варианты рецептов по пройденным урокам (сначала теги с наименьшей точностью); если и их нет —
   занятие короче.
4. Не больше 2 заданий из одного рецепта подряд и не больше 4 на занятие (чтобы не было монотонно).
5. Письмо — как сейчас, раз в 3 дня.

Занятие нового материала не меняется (8 заданий порции + 2 на повторение); эти 2 берутся по тем же
весам из пункта 3.

«Повторение урока» (когда порции урока кончились и точность < 70%) берёт задания текущего урока
тем же алгоритмом, но только `lessonNo = текущий`.

Случайность — через инъекцию генератора (`rand: () => number`) в планировщик, чтобы тесты были
детерминированными.

### Запас (`status`, сводка после занятия)
Задания больше не кончаются, поэтому «запас» считается только по порциям нового материала:
`days = portionsReady`. Предупреждение «заданий мало» — когда порций < 2. В `status` дополнительно
показываются: сколько заданий в обороте, сколько из них к показу сегодня, сколько рецептов и
вариантов, распределение по score, слабые и освоенные теги.

## Часть 2. Рецепты упражнений

### Что такое рецепт
Рецепт — запись в банке (новая таблица `recipes`), которую Claude добавляет через `bank add`
вместе с порциями и заданиями. Один вид рецепта в коде на старте — **`form`** («поставь слово
в нужную форму в рамке-предложении»). Он покрывает: спряжение (*būti*, *kalbėti*), падежи
(*iš* + род.), а через опции-ответы — выбор по роду (*koks/kokia*).

Формат во входном JSON (`bank add`):
```json
{
  "recipes": [
    {
      "kind": "form",
      "lessonNo": 2,
      "tags": ["verb:būti"],
      "explanation": "aš esu, tu esi, jis/ji/jie/jos yra, mes esame, jūs esate",
      "frames": [
        { "lt": "Aš ___ studentas.", "key": "pres.1sg" },
        { "lt": "Tu ___ mano draugas.", "key": "pres.2sg" },
        { "lt": "Jos ___ mano draugės.", "key": "pres.3", "note": "jos → yra" }
      ],
      "words": ["būti"],
      "present": ["input", "choice", "order"]
    },
    {
      "kind": "form",
      "lessonNo": 4,
      "tags": ["prep:iš+gen", "case:gen:sg"],
      "explanation": "После iš — родительный падеж: -a → -os",
      "frames": [
        { "lt": "Aš esu iš ___.", "key": "gen.sg" },
        { "lt": "Mano draugas yra iš ___.", "key": "gen.sg" }
      ],
      "words": ["Lietuva", "Rusija", "Ukraina", "Latvija"],
      "present": ["input", "choice"]
    }
  ]
}
```
Поля:
- `frames[].lt` — литовская фраза с одним `___`; `key` — ключ формы лексикона (как в `target`);
  `note` — необязательная добавка к объяснению для этой рамки.
- `words` — леммы, которые подставляются в рамку.
- `present` — в каком виде бот может показать вариант (подмножество `input`, `choice`, `order`).
- `options` (необязательно, для выбора по роду) — см. ниже.

**Выбор по роду (*koks/kokia*).** Тот же `form`, но вместо формы слова пробел заполняет слово,
выбранное по роду существительного:
```json
{
  "kind": "form", "lessonNo": 3, "tags": ["gender", "introduce"],
  "explanation": "koks — с мужским родом, kokia — с женским",
  "frames": [ { "lt": "___ jūsų {word}?", "key": "nom.sg" } ],
  "words": ["vardas", "pavardė", "telefonas", "šalis", "kalba"],
  "byGender": { "m": "Koks", "f": "Kokia" },
  "present": ["choice"]
}
```
Здесь `{word}` заменяется формой слова по `key`, а ответ — `byGender[род слова]`; варианты кнопок —
все значения `byGender`. Род берётся из лексикона.

### Развёртка рецепта (в CLI, при `bank add`)
CLI проверяет рецепт и превращает его в список **вариантов** (рамка × слово), каждый с готовыми
данными, чтобы боту не нужен был лексикон:
- `question` — рамка, в которой `___` оставлен, а `{word}` подставлен; к вопросу добавляется
  подсказка `(лемма)` для режима формы;
- `answer` — форма из лексикона (`lex.form(lemma, key)`, первый вариант) или `byGender[род]`;
- `accept` — все варианты формы из лексикона для этого ключа (например, `kalbame/kalbam`);
- `reject` — формы того же слова, которые без диакритики совпадают с ответом (та же проверка, что
  сейчас в `validateTask`);
- `distractors` — до 3 других **реальных** форм того же слова, отличных от ответа (для кнопок):
  сначала формы того же числа/времени, потом остальные; для `byGender` — другие значения;
- `orderWords` — фраза с подставленной формой, разбитая на слова (знаки препинания остаются внутри
  слов), если в `present` есть `order` и в фразе ≥ 3 слов.

Проверки (вариант с ошибкой отбрасывается, рецепт без единого варианта — отклоняется целиком):
- формы нет в лексиконе (в т. ч. слово только с `keyForms`, где нужной формы нет) → вариант пропущен
  с предупреждением;
- все литовские слова рамки и все `words` — из лексикона и изучены к уроку рецепта (как задания);
- `byGender` — у слова в лексиконе есть род;
- для `choice` нужно ≥ 1 дистрактора (иначе этот вид у варианта не показывается).

`bank add` печатает по рецепту: «✓ рецепт verb:būti (урок 2): 15 вариантов» или причины отказа.
Отклонённое Claude исправляет и отправляет только отклонённое (как сейчас).

### Как бот делает задание из варианта
Когда планировщику нужен вариант рецепта (часть 1, шаги 2–3), он выбирает рецепт (сначала по
слабым тегам, затем по наименьшей точности тегов) и вариант, который ещё не превращён в задание.
**Один вариант (рамка × слово) = одно задание**: вид показа выбирается случайно из `present`
варианта один раз, при создании. Бот **создаёт обычное задание** в таблице `tasks`
(`slot = review`, теги и урок рецепта, `recipeId`, `variantKey = "<индекс рамки>#<лемма>"`):
- `input`: вопрос с `___` и подсказкой, `accept`, `reject`, `target = {lemma, key}`;
- `choice`: вопрос, варианты = ответ + дистракторы в случайном порядке;
- `order`: вопрос «Соберите фразу» + перемешанные `orderWords`, `accept` = собранная фраза.
Объяснение = `explanation` рецепта + `note` рамки.

Дальше это обычное задание: оно вращается со счётчиком, его можно оспорить, ошибки по нему идут в
слабые места. Пара (`recipeId`, `variantKey`) уникальна — одно и то же задание не создаётся дважды.
Когда все варианты рецепта уже превращены в задания, рецепт больше ничего не добавляет: дальше
работают возврат и счётчики.

### Имя рецепта, замена и вывод из оборота
- У рецепта обязательное поле `name` (уникальное, латиница/цифры/`-`, например `buti-pres`,
  `is-gen-countries`). Это ключ рецепта.
- `bank add` с рецептом, `name` которого уже есть, **заменяет** его: варианты пересчитываются;
  задания этого рецепта, чьего `variantKey` больше нет или чей ответ изменился, получают
  `status = retired` (больше не выдаются); остальные сохраняют счётчики.
- Новая команда CLI `recipes retire <name>` — выводит рецепт и все его задания из оборота.
- `disputes resolve` получает необязательное поле `retireTask: true` — вывести из оборота задание
  с ошибкой в самом задании (например, неверная рамка). Claude затем исправляет рецепт заменой.
- `retired` задания не выдаются и не считаются в запасе.

### Работа Claude (скилл `lit-generate`)
- В формат `bank add` добавляется раздел `recipes`.
- Цель пополнения: к каждому пройденному уроку — рецепты на его грамматику; к каждому слабому тегу
  без рецепта — рецепт. Заданий на закрепление можно писать меньше (пул больше не тает):
  перевод, чтение, письмо и то, что рецептом не выразить.
- Первые рецепты на уроки 1–4: *būti* (все лица), *koks/kokia* по роду, *iš* + род. (страны),
  *kalbėti* (все лица).
- В `status` — раздел про рецепты (сколько вариантов осталось незадействованными по каждому).

## Данные (миграция `0003`)
- `tasks`: `score smallint not null default 0`, `due_at timestamptz` (null → считается `created_at`),
  `recipe_id uuid references recipes(id)`, `variant_key text`; уникальный индекс
  (`recipe_id`, `variant_key`) где `recipe_id is not null`; индекс по (`due_at`).
- `recipes`: `id uuid`, `name text unique`, `kind text`, `lesson_no int`, `tags text[]`, `payload jsonb` (входной рецепт),
  `variants jsonb` (развёрнутые варианты), `created_at timestamptz`.
- Существующие задания: `score = 0`, `due_at = null` → все показанные ранее задания сразу снова в обороте.
- `Store` (память и Supabase): `listRotatingTasks(now, maxLesson)`, `updateTaskScore(id, score, dueAt)`,
  `addRecipes`, `listRecipes`, создание задания из варианта с защитой от дубля.

## Что меняется в коде (ориентир для плана)

- `cli/commands.ts` — `bank add` принимает `recipes`; `status` показывает новое.

- Тесты на всё перечисленное, в т. ч. детерминированный выбор с фиксированным `rand`.

## Решения Claude (пользователь может поправить)
- Интервалы `[1, 3, 7, 14, 30, 60]` дней по новому score, в днях пользователя; ошибка → score 0;
  без диакритики — счётчик не растёт.
- Спор: score 2 сразу; вердикт «неверно» → score 0.
- Один вариант рецепта = одно задание, вид показа выбирается при создании.
- Рецепты именуются; повторный `bank add` заменяет рецепт; `recipes retire` и `retireTask` для исправлений.
- Пороги слабого/освоенного тега и множители 3 / 0.3.
- В занятии закрепления 3 карточки слов + 10 заданий, ≥ 6 по слабым темам.
- Задания порций тоже уходят в повторение.
- Один вид рецепта `form` (+ `byGender`) на старте; другие виды — по мере надобности.

## Оставлено исполнителю
- Точный алгоритм взвешенного выбора без повторов и как именно ограничивать «не больше 2 подряд из
  одного рецепта».
- Порядок дистракторов и формат вопроса «Соберите фразу».
- Тексты в `status` и в сводке после занятия.
